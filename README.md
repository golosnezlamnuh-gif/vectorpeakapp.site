# Cold Open: сайт про нові серії серіалів (Cloudflare Pages + Google AdSense)

Статичний сайт англійською мовою: щодня показує, які нові серії виходять на ТБ і стрімінгах (США, Велика Британія, Канада, Австралія), з часом у часовому поясі відвідувача, короткими «брифами» до найцікавіших серій, прем'єрами на два тижні вперед, підпискою на серіали та експортом у календар. Без бекенду, без бази даних, без платних сервісів.

Назва «Cold Open» умовна (так у серіалах називають вступну сцену перед заставкою). Змініть її в `site.config.json`.

---

## 1. Спершу чесно: що безкоштовно, а що ні

| Що | Вартість |
|---|---|
| Cloudflare Pages (хостинг, HTTPS, CDN) | безкоштовно |
| GitHub + GitHub Actions (щоденне оновлення) | безкоштовно |
| TVmaze API (розклад, описи, акторський склад) | безкоштовно, ліцензія CC BY-SA 4.0 (атрибуція вже є у футері) |
| Google AdSense | безкоштовно (Google платить вам, а не навпаки) |
| **Власний домен** | **≈ 10 USD на рік**. Це єдина річ, яка не безкоштовна, і я раджу її не оминати (див. розділ 5) |

Ще три речі, які краще знати наперед:

1. **Схвалення AdSense не гарантоване.** Google вирішує сам, зазвичай від кількох днів до кількох тижнів. Сайт зроблений так, щоб пройти перевірку (є політика конфіденційності, контакти, про сайт, реальний щоденний вміст), але обіцяти результат не можна.
2. **Без відвідувачів дохід дорівнює нулю.** Конкуренція за запити на кшталт «tv schedule today» дуже висока (TV Guide, TV Insider та інші). Реалістична ніша сайту: «що нового виходить сьогодні в моєму часовому поясі», прем'єри, архів днів. Це довга гра: перші місяці йде індексація.
3. **Я не міг перевірити роботу з живим TVmaze.** У моєму середовищі доступ до api.tvmaze.com заблокований, тому все протестовано на фікстурах, які повторюють формат відповідей із документації (формат перевіряє збірка, див. розділ 3, крок «Перший запуск»). Після першого запуску відкрийте сайт і подивіться, чи прийшли дані. Якщо щось не так, збірка зупиниться з зрозумілим повідомленням і нічого не зламає.

## 2. Як сайт «оновлюється щодня»

Два рівні, які доповнюють один одного:

- **Рівень 1, живі дані.** Щоразу, коли хтось відкриває сайт, браузер сам запитує TVmaze. Тож розклад завжди актуальний і не залежить від того, чи ви щось перезбирали.
- **Рівень 2, щоденна «збережена копія».** Раз на добу GitHub Action запускає `node tools/build.mjs --daily`, який завантажує розклад і записує готові HTML-сторінки: головну на сьогодні, **нову постійну сторінку дня** `/day/РРРР-ММ-ДД/` (архів зростає щодня), прем'єри на 14 днів, `sitemap.xml`. Ці сторінки Google бачить без виконання JavaScript. Саме вони потрібні для індексації й для перевірки AdSense: щодня з'являється нова адреса з новим вмістом.

Що саме є «унікальним» у вмісті: текст-резюме дня обчислюється з даних (кількість серій і шоу, прем'єри, найзавантаженіший слот, найпопулярніше шоу), добірка «Picks of the day» складається за відкритою формулою (описана на сторінці `/how-it-works/`), прем'єри й архів зведені в окремі сторінки. Але описи серій узято з TVmaze, тож «повністю унікальним» цей текст не є. Найсильніший спосіб це виправити: **писати Editor's note** (розділ 9). Це 2 хвилини на день.

## 3. Швидкий старт

Потрібно: Node.js 20 або новіший (для збірки), акаунт GitHub, акаунт Cloudflare.

### Крок 0. Налаштуйте `site.config.json`

```json
{
  "siteName": "Cold Open",
  "tagline": "Every new TV episode of the day, in a few lines.",
  "siteUrl": "https://example.com",
  "contactEmail": "hello@example.com",
  "editorName": "the Cold Open editor",
  "defaultRegion": "US",
  "adsense": { "publisherId": "", "slots": { "side": "", "feed": "", "end": "" } }
}
```

- `siteUrl`: адреса сайту з `https://` (ваш домен, або тимчасово `https://назва.pages.dev`). Використовується в canonical, sitemap, robots.txt.
- `contactEmail`: **створіть для сайту окрему поштову адресу** і впишіть сюди. Вона публічна (сторінка Contact), тож не використовуйте особисту.
- `editorName`: ім'я або псевдонім, яке з'явиться на сторінці About.
- `adsense`: залиште порожнім, доки не отримаєте схвалення (розділ 6).

Поки там `example.com`, збірка пише попередження.

### Варіант A. Найшвидший (5 хвилин, без автоматики)

1. `node tools/build.mjs`: збере папку `site/`.
2. Cloudflare → **Workers & Pages → Create → Pages → Upload assets**, назва проєкту, перетягніть папку `site` (або ZIP з нею), **Deploy**.
3. Сайт на `назва.pages.dev` працює відразу, дані живі (рівень 1). Збереженої щоденної копії не буде, тож для SEO й AdSense цього замало.

Мінус: проєкт, створений через Upload, потім не можна перемкнути на Git (обмеження Cloudflare). Для щоденної автоматики оберіть варіант B.

### Варіант B. Рекомендований: GitHub + Cloudflare + щоденна автоматика

1. Створіть репозиторій на GitHub (можна приватний) і завантажте весь проєкт, **разом із папкою `site/`**:
   ```bash
   git init && git add -A && git commit -m "Cold Open"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГІН/cold-open.git
   git push -u origin main
   ```
2. Cloudflare → **Workers & Pages → Create → Pages → Connect to Git** → оберіть репозиторій. Налаштування збірки:
   - Framework preset: **None**
   - Build command: **порожньо**
   - Build output directory: **`site`**
3. На GitHub → **Actions → Daily update → Run workflow**. Це **перший запуск**: Action завантажить сьогоднішній розклад із TVmaze, закомітить оновлену папку `site/`, а Cloudflare автоматично опублікує її. Далі воно щодня о 06:20 UTC.
4. Відкрийте сайт і перевірте: головна показує розклад на сьогодні, є сторінка `/day/РРРР-ММ-ДД/`, прем'єри заповнені. Якщо Action упав, у логу буде причина (наприклад, «Only 0 episodes came back», і тоді старий сайт залишається недоторканим).

Примітка: GitHub може призупинити розклад у публічних репозиторіях без активності 60 днів. Щоденні коміти зазвичай цьому запобігають, але якщо розклад зупинився, натисніть **Enable workflow** на вкладці Actions.

### Варіант C. Вручну на своєму комп'ютері

Щодня: `node tools/build.mjs --daily`, потім завантажити `site/` у Cloudflare (Upload або `wrangler pages deploy site`). Для тесту без інтернету: `node tools/build.mjs --daily --fixtures tests/fixtures.mjs --out /tmp/test-site`.

## 4. Параметри збірки

```
node tools/build.mjs                 зібрати site/ із src/ та site.config.json (без завантаження даних)
node tools/build.mjs --daily         + завантажити розклад і записати збережені сторінки
  --date 2026-11-10                  зібрати для іншої дати (за східним часом США)
```

Збірка захищена від збоїв: якщо API відповів не списком або повернув менше 5 серій, вона зупиняється і **не чіпає** попередній сайт.

## 5. Домен: чому я раджу купити свій

Офіційна сторінка вимог AdSense ([support.google.com/adsense/answer/9724](https://support.google.com/adsense/answer/9724)) прямо не забороняє піддомени й не вимагає власного домену. Вона вимагає вік 18+, доступ до HTML-коду сайту та вміст, який має бути «high-quality, original, and attract an audience». Водночас вебмайстри часто повідомляють про відмови для сайтів на безкоштовних піддоменах платформ (`*.pages.dev`, `*.vercel.app`, `*.github.io`). Це неофіційні відгуки, тому сприймайте їх як ризик, а не як правило. Власний домен підвищує довіру до сайту, залишається вашим, якщо ви колись змінюватимете хостинг, і потрібен для нормального SEO (бренд, стабільні адреси).

- Найдешевше й найпростіше: купити домен прямо в Cloudflare (**Domains → Register**, продають за собівартістю) або в будь-якого реєстратора й вказати NS Cloudflare.
- Підключення: проєкт Pages → **Custom domains → Set up a domain**. SSL автоматичний. Підключення домену безкоштовне.
- Після підключення: впишіть домен у `siteUrl` і збережіть зміни (коміт запустить повторне розгортання).

Домен у зоні `.com` коштує порядку 10 USD на рік. Точну ціну дивіться в реєстратора.

## 6. AdSense: покроково

Я не перевіряв в акаунті поточні умови виплат і податкові форми. Дивіться актуальне в довідці AdSense. Ви вже працюєте з AdMob, тож платіжний профіль Google у вас, імовірно, є, але AdSense це окремий продукт із власною перевіркою.

1. **Підготуйте сайт.** Має працювати на вашому домені, мати вміст (запустіть варіант B і дочекайтеся кількох щоденних сторінок), сторінки Privacy, Terms, Contact, About (вони вже є й коректно оформлені).
2. **Впишіть Publisher ID** у `site.config.json`: `"publisherId": "pub-1234567890123456"` (знайдете в AdSense → Account → Settings). Закомітьте. Збірка сама:
   - додасть у `<head>` потрібних сторінок мета-тег `google-adsense-account` і скрипт AdSense;
   - створить `ads.txt` (`google.com, pub-…, DIRECT, f08c47fec0942fa0`);
   - додасть у футер посилання `Privacy and cookie settings`;
   - допише на сторінці Privacy розділ про рекламу.
   Реклама ще **не показується**, поки не вказані слоти (крок 5).
3. **Додайте сайт** в AdSense → Sites → Add site, пройдіть перевірку (скрипт уже є на сторінці) і чекайте рішення.
4. **Згода (GDPR).** AdSense → Privacy & messaging → створіть повідомлення для ЄС/Великої Британії/Швейцарії (GDPR) і для штатів США (за потреби) та опублікуйте. Це обов'язково для трафіку з ЄЕЗ/Великої Британії: потрібен сертифікований CMP, і саме це робить Google Privacy & messaging. Посилання `Privacy and cookie settings` у футері дає відвідувачам змогу змінити вибір.
5. **Після схвалення створіть 3 рекламні блоки** (AdSense → Ads → By ad unit → Display ads, **Responsive**): `side`, `feed`, `end`. Скопіюйте числовий ID кожного (`data-ad-slot`) у конфіг:
   ```json
   "adsense": { "publisherId": "pub-…", "slots": { "side": "1234567890", "feed": "2345678901", "end": "3456789012" } }
   ```
   Закомітьте. Реклама з'явиться після розгортання. Слот без ID просто не створюється.
6. Дивіться на будь-якій сторінці `?adpreview=1`, щоб побачити, де будуть блоки, ще до їх активації.

Чого не робити: не натискайте на власну рекламу, не просіть інших, не ставте блоки поверх кнопок. Для цього в коді закладено запобіжники.

## 7. Куди ставити рекламу: моя порада

Ви просили «блок або порадь, що краще». Я зробив три ручні блоки, бо вони дають контроль і не псують читання:

| Блок | Де | Чому |
|---|---|---|
| `side` | права колонка на десктопі (липкий, під «Picks of the day») | видно весь час прокручування, не заважає змісту |
| `feed` | у розкладі між групами часу (після 3-ї групи, далі кожна 5-та, максимум 3 на сторінку) | найкращий компроміс між доходом і зручністю: пауза між часовими слотами |
| `end` | кінець сторінки серіалу | користувач дочитав, клік найімовірніший |

Правила, які сайт виконує сам:
- підпис **«Advertisement»** над кожним блоком;
- блоків немає на екранах завантаження, помилки, порожнього результату, на сторінках Privacy/Terms/Contact/About/404/Search/«My shows»;
- в стрічці блоки з'являються лише коли в списку **8 і більше серій** і діють фільтри за замовчуванням, а при перемиканні фільтрів не оновлюються (автоматичне оновлення реклами AdSense не схвалює);
- якщо Google не має реклами для показу, порожній блок згортається й не залишає дірки в сторінці.

**Чого б я не робив на старті:** Auto ads (Google сам розставить банери, зокрема липкий знизу й повноекранні, а це шкодить зручності та швидкості), більше трьох блоків на сторінку, рекламу вгорі над заголовком на мобільних. Через 3–4 тижні подивіться звіт AdSense по блоках: слабший блок приберіть, сильніший можна дублювати. Якщо захочете більше доходу, пробуйте якірну рекламу на мобільних як експеримент і дивіться на відмови.

Дохід ≈ (перегляди сторінок / 1000) × RPM. RPM для англомовного розважального контенту із США/Великої Британії/Канади/Австралії зазвичай у межах кількох доларів на 1000 переглядів. Це мої орієнтовні припущення, а не обіцянка: усе залежить від країн відвідувачів і сезону.

## 8. Приватність і юридичне

- Сторінки Privacy і Terms уже є й автоматично змінюються, коли ви вмикаєте рекламу. Вони описують localStorage (ваші «підписки» зберігаються лише в браузері), Cloudflare, TVmaze та AdSense. Це шаблони загального призначення, а не юридична консультація.
- **TVmaze, CC BY-SA 4.0:** комерційне використання дозволене за умови атрибуції (є у футері на кожній сторінці). Умова ShareAlike означає, що відомості, взяті з TVmaze, залишаються під тією ж ліцензією (це сказано на сторінці Terms). Дизайн і код ваші.
- Шрифти Archivo і Literata під ліцензією SIL OFL, файли ліцензій лежать поруч зі шрифтами (`src/assets/fonts/`).
- Сайт не розміщує й не стрімить відео, лише розклад, тож проблем із авторським правом на контент немає. Назви каналів і шоу вживаються лише для ідентифікації.

## 9. Що робити вам, щоб сайт ріс

1. **Editor's note (2 хвилини на день).** Створіть файл `content/notes/РРРР-ММ-ДД.txt` (дата за східним часом США) на 2–4 абзаци англійською: що ви б дивилися сьогодні й чому. Ці тексти потрапляють на головну й у постійну сторінку дня. Це справжній ваш вміст, і найкращий сигнал якості для читачів та Google. Файл можна створити просто в вебінтерфейсі GitHub зі смартфона. Тест: `node tools/build.mjs --daily --notes content/notes`.
2. **Search Console.** Додайте сайт у Google Search Console, надішліть `https://ваш-домен/sitemap.xml`. Індексація починається не відразу.
3. **Не множте сторінки заради сторінок.** Політика Google проти «масового створення вмісту» (scaled content abuse) спрямована проти великої кількості тонких автоматичних сторінок. Тому сторінки серіалів, пошук і «My shows» закриті від індексації (`noindex`): у пошук ідуть лише сторінки з реальним щоденним змістом.
4. **Наступний крок розвитку (поки не зроблено):** статичні сторінки для серіалів, що виходять сьогодні («When does X air next?»), які оновлюються щодня. Це найсильніший довгий хвіст для пошуку. Доцільно робити, коли з'явиться перший трафік, і лише з реальним змістом. Скажіть, і я доробимо.
5. Дивіться на AdSense Policy Center раз на тиждень, перші місяці це важливо.

## 10. Структура проєкту

```
site.config.json        налаштування (назва, домен, email, AdSense)
content/notes/          ваші Editor's note (РРРР-ММ-ДД.txt)
src/pages/*.html        шаблони сторінок
src/assets/js/render.js  спільний код відображення (браузер і збірка)
src/assets/js/app.js     поведінка сторінок (дні, регіони, фільтри, Follow, календар…)
src/assets/js/ads.js     вставка рекламних блоків (лише налаштованих)
src/assets/css/site.css  стилі
src/static/_headers      заголовки Cloudflare Pages (безпека, кеш)
tools/build.mjs         збирач (Node 20+, без залежностей)
tests/                  юніт-, статичні та браузерні тести
.github/workflows/daily.yml  щоденне оновлення
site/                   готовий до публікації результат збірки
```

Статичні перевірки: наявність файлів, биті посилання, унікальність id, sitemap без noindex-сторінок, реклама лише на потрібних сторінках, відсутність особистих адрес і шляхів у результаті, збір із різними конфігураціями. Браузерні: перемикання днів/регіонів, фільтри, «Follow», календар (.ics), сторінка серіалу, пошук, помилки API (429, 500), реклама, захист від XSS, відсутність горизонтальної прокрутки на 320–1280 px, клавіатура, зменшений рух.

## 12. Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| Головна показує «We could not reach the TV data service» | TVmaze недоступний або вас тимчасово обмежено (429). Сайт пробує ще кілька разів; натисніть Try again пізніше |
| Action падає з «Only N episodes came back» | У TVmaze збій або порожній день. Старий сайт залишився як був. Запустіть повторно пізніше |
| Реклама не показується | Чи вказані `publisherId` і слоти; чи схвалено сайт; чи не блокує її ваш блокувальник реклами; відкрийте `?adpreview=1`; нові блоки з'являються через кілька годин |
| «Ads.txt not found» в AdSense | Файл `ads.txt` створюється лише при заданому `publisherId`; домен має відкривати `/ads.txt` без перенаправлення на інший хост |
| Canonical показує example.com | Не змінено `siteUrl` у конфігу |
| Дати «з'їхали» на день | Дні сайту рахуються за календарем мовлення обраного регіону; час перераховується під ваш пояс, з позначкою дня тижня, коли дата відрізняється |
